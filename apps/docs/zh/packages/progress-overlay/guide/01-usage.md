# 使用指南

## 句柄

`showProgressOverlay(options)` 返回只有三个方法的句柄，全部异常安全、`close()` 之后调用也无害：

- `setProgress(p)` — 喂进度值。`(0, 1)` 区间任何一个值都会把遮罩切到确定态进度条。入口的 `0` 被忽略；收尾的 `1` 只会把已存在的确定态推满——全程没有中间进度的任务会一直停在圆环上（这是数据源粒度，不是渲染问题）。
- `setPhase(key)` — 按 `text.phases` 表切换文案。
- `close()` — 幂等。挂在 `finally` 里；绝不能由 `setProgress(1)` 触发关闭——失败路径同样会发收尾的 1。

## 配置项

| 配置项             | 默认值          | 说明                                                                                           |
| ------------------ | --------------- | ---------------------------------------------------------------------------------------------- |
| `delayMs`          | `200`           | 挂载遮罩前的延迟。比它更快的任务根本不会显示遮罩。                                             |
| `minVisibleMs`     | `300`           | 一旦显示就至少停留这么久——移除走延时，而不是一闪而过。                                         |
| `fadeOutMs`        | `150`           | 节点移除前的淡出时长。                                                                         |
| `zIndex`           | `2147483000`    | 遮罩层级。                                                                                     |
| `container`        | `document.body` | 挂载容器。                                                                                     |
| `blockInteraction` | `true`          | 在遮罩自身上拦截指针与滚动事件（绝不改宿主页面的 `overflow`）。置 `false` 时下层页面仍可操作。 |
| `theme`            | `"auto"`        | `"auto"` 在挂载时按 `prefers-color-scheme` 解析。                                              |
| `text.title`       | `"请稍候"`      | 面板标题。                                                                                     |
| `text.initial`     | `"正在处理…"`   | 收到首个 `setPhase` 前的文案。                                                                 |
| `text.phases`      | `{}`            | `key → 文案` 表；`setPhase(key)` 时查表。未覆盖的 key 原样显示。                               |
| `text.hint`        | （见上）        | 文案下方的补充行，仅不确定态显示。                                                             |

## 主线程阻塞

任务里**同步**的长耗时段落（一口气构建大对象、同步式处理）会约束遮罩的行为，因为浏览器无法在任务中间重绘：

- 默认 `delayMs: 200` 时，如果延迟到期那会儿阻塞已经开始，显示会被饿死：这次任务**根本不会出现遮罩**。迟到的定时器在关闭时会被显式清掉，所以它也绝不会在任务结束**之后**才弹出来。
- `delayMs: 0` 时遮罩在任务开始前同步挂载。在 `showProgressOverlay` 与阻塞调用之间 await `nextPaint()`（本包导出）——这次让出是浏览器能绘制出遮罩的唯一保证，代价是快任务会闪一下。

两种配置下，阻塞期间动画都会继续（CSS transform 动画由合成器驱动），而百分比与文案会冻结到线程空闲为止。

```ts
const overlay = showProgressOverlay({ delayMs: 0 });
try {
  await nextPaint(); // 先让浏览器画出遮罩
  heavySyncWork(); // 阻塞段——遮罩可见且动画在跑
} finally {
  overlay.close();
}
```

`nextPaint()` 让出两帧，并与一个 250ms 定时器竞速：不可见页面（rAF 被无限期暂停）里定时器获胜，后台任务不会挂在这次让出上。

## 并发

遮罩共用一个 DOM 节点并做引用计数：并发任务渲染进同一个遮罩（最后更新者为准），最后一个关闭时才移除。共享节点带来两个结果：

- 遮罩尚未显示时第二个任务介入，揭开会等到所有并发调用方的 `delayMs` 都过完——delay 更长的后来者不会被首个任务的定时器提前揭开。
- 遮罩已显示时第二个任务介入，在 `show` 时刻立即接管显示（标题/提示/文案一并刷新为它的），而不是等自己的第一个进度/阶段事件。

早退调用方挂起的揭示定时器到点时，显示的文案属于最近介入且仍活动的调用方。

## Node 与 SSR

没有 `document` 时，`showProgressOverlay` 返回空实现句柄——同一处调用代码在两种环境下都可用，无需分支。

## 无障碍

进度条带 `role="progressbar"`（仅确定态下附带 `aria-valuenow`），文案节点是 `aria-live="polite"` 的状态区域，圆环是 `aria-hidden` 装饰，容器设置 `aria-busy`。百分比是独立节点、不进 live 区域，读屏不会每次进度跳动都重播。

阻断只做在指针层面，遮罩**有意不**对下层页面施加 `inert`——键盘用户仍能 Tab 到视觉上被盖住的元素。把每个兄弟节点都置为 `inert` 侵入性太强，有破坏宿主页面行为的风险，因此没有采用。

## 从 @marcusok 业务包使用

`@marcusok/excel-exporter` 2.8+ 默认启用本遮罩（`overlay: false` 关闭，`overlay: {…}` 定制）并提供导出语义文案。自定义流程想自己驱动句柄时，可从 `@marcusok/excel-exporter/overlay`（历史子路径）取转发绑定——或直接 import 本包、用你自己的阶段 key。
