# 能力边界

本包明确不做的事，以及原因。

## 不支持（友好报错）

| 场景                                                          | 行为                                                                                                                                                         |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 旧版 `.xls`（BIFF8）                                          | `LEGACY_FORMAT` 错误，附"另存为 .xlsx"提示。OLE2/BIFF 是完全异构的二进制世界；将来可选 adapter 引入 SheetJS，但本包保持依赖链干净。                          |
| `.ods` 等其他套件（同为 ZIP）                                 | `CORRUPT` 错误——它们是 ZIP 包但没有 `xl/workbook.xml`，按"不是有效 xlsx"报错。                                                                               |
| XML/HTML 伪表格（SpreadsheetML 2003、HTML 表格另存的 `.xls`） | `UNSUPPORTED` 错误——它们是文本但不是 CSV，按数据网格渲染没有意义；请另存为真正的 `.xlsx`。                                                                   |
| 损坏数据                                                      | ZIP 结构破损（截断等）或工作簿一个 sheet 都没有 → `CORRUPT`；连 ZIP 都不是、也嗅探不出文本 → `UNSUPPORTED`（格式无法判定）。                                 |
| 无 WebAssembly 的环境 / 引擎加载失败                          | `WASM` 错误——xlsx 解析仅走 WASM 引擎（没有纯 JS 的 xlsx 降级读取器）；资产 404、CSP 禁止 WebAssembly、网络失败同样报 `WASM`。CSV 无需 WebAssembly 仍可解析。 |

## 已知近似的渲染

- **富文本** runs 渲染为拼接纯文本；runs 级样式在路线图上（当前模型只保留拼接文本，还原 runs 需要补解析）。
- **图案填充**（`gray125` 这类斜纹）以底色/前景色的纯色近似；纯色与渐变填充精确渲染。
- **旋转文本**（`textRotation`）放不下时按格子矩形裁剪——Excel 同样截断超出格子的旋转文本，但其裁剪沿旋转后的文本走向而非轴对齐的格子矩形，对角线附近的边缘形态略有差异。
- **窄于内容的数字列**直接裁剪，不显示 Excel 的 `####`（真 `####` 需要逐格文本测量，不值得为之付出滚动成本）。
- **超大合并**放弃逐格展开：单条合并覆盖格数（`rowSpan × colSpan`）超过 100 万，或全部合并的展开总量累计超过 200 万格（预算按文件顺序先到先得）即触发：合并主格仍按跨度渲染，但覆盖格不再被置空，此类合并内残留的零星残值会显示出来（Excel 语义下应为空）。设此上限是因为展开在主线程逐格进行——全表合并、或多条压线合并叠加，都会直接冻结页面。
- **首次模型回传**在主线程执行：worker 在后台解析，但完成的 `PreviewWorkbook` 需结构化克隆回来，这是一段随单元格数增长的主线程任务（Chromium 实测 1 万行约 50ms、5 万行约 150ms、10 万行约 300ms）。滚动与渲染仍是虚拟化的；解析结束时会短暂停顿，解析过程中不会。
- **Node 运行时敏感性**：Node 22.x（以及 Node 24.14）上，内置引擎的 `readBuffer` 对数字密集表比 Node 24.21 慢约 10 倍。包仍可用，但浏览器/锁定运行时的性能数字不适用；支持矩阵见仓库 README。
- **拆分窗格**（`splitPane`）被忽略——只有冻结窗格渲染（模型只携带 `frozenPane`）。
- **页签颜色**不携带（页签栏不显示工作表的页签颜色）；单元格批注同样在读取侧被丢弃。
- **外部超链接 URL** 不渲染；超链接*样式*（文件字体的蓝/下划线）仍会显示——它就是普通字体数据。tooltip 同样不展示。
- **`rightToLeft` 工作表**暂按从左到右渲染（标志已解析进模型）。
- **条件格式**与数据条/图标集不应用。
- **图表、图片、形状**不渲染。
- **行列分组**（outline 层级）不解析、不绘制。

## CSV 编码

自动识别 UTF-8（有无 BOM 均可）与 GB18030。UTF-16 的 CSV 通常过不了文本嗅探——
不是因为识别到了它的 BOM（`FF FE` / `FE FF`），而是 UTF-16 字节流充满 NUL、
嗅探要求前 2KB 可打印字节占比 ≥ 95%。它们因此落入 `unknown` 并以
`UNSUPPORTED` 拒绝——请先另存为 UTF-8（极端构造的高可打印 UTF-16 流
仍可能漏过嗅探、被按乱码解码而非拒绝）。

## 公式

公式单元格渲染**缓存**的 `<v>` 值——与 SheetJS（"SheetJS does not evaluate formulas"）和 exceljs 同一约定。非 Excel 写入器保存的公式若无缓存值，渲染为空单元格。

## 规模上限

解析不是流式的（OOXML 部件间交叉引用，浏览器无法流式解析互相依赖的 zip 部件）——整个文件在 worker 内读入内存。10 万行 × 10 列解析实测约 1.5s；虚拟滚动保证 DOM 恒为视口规模。数百 MB 的文件会先撞内存上限。
（仓库内性能测试的验收阈值是另一个口径：10 万行 × 8 列解析 + 模型构建 < 4s，在 happy-dom 内测、不含真实渲染；CI 与发布链路以 `RUN_PERF=0` 跳过。）

**行数上限（浏览器而非内存限制）**：整个网格是一个撑高的容器元素，行高按 20px（15pt）算，约 89 万行（约 1790 万 px）就会触到 Firefox / Safari 的元素尺寸上限，此时尾部行不可达；Chrome 的上限约 3350 万 px（约 167 万行）。表头与行列标仍按视口渲染，只有滚动范围被截断。整表 1,048,576 行恰好落在两个上限之间（20px 行高约 2100 万 px——Chrome 可达、Firefox / Safari 被截断）；行高再大一些则所有浏览器都会超限。
